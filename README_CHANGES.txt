از ریشه‌ی ریپو extract کن (روی فایل قبلی می‌شینه):

  src/back/app/static/review.html   ← فینیش دیگه دست خریدار/کارفرما نیست

--------------------------------------------------------------------------
مشکل
--------------------------------------------------------------------------
توی پنل ۳ (پیش‌نمایش لایو)، یه سلکتور «فینیش» بود که با انتخاب دستی می‌تونست
category محصول رو دور بزنه (currentFinish() توی JS). این سلکتور همیشه توی
صفحه‌ی /review دیده می‌شد — یعنی حتی توی نمای «کارفرما» (?client=1)، که خودِ
خریدار/کارفرما می‌بینه، هم فعال بود. اما طبق منطق پروژه، فینیش (مات/براق/...)
باید فقط از روی نوع محصولی باشه که فروشنده موقع ساخت محصول انتخاب کرده —
نه یه چیز قابل‌انتخاب لحظه‌ای برای بیننده.

--------------------------------------------------------------------------
تغییر
--------------------------------------------------------------------------
- سلکتور «فینیش» و لیبلش توی یه <span id="liveFinishGroup"> پیچیده شدن.
- توی init()، وقتی CLIENT_VIEW (یعنی ?client=1) هست، همین گروه با کلاس
  hidden مخفی می‌شه — دقیقاً مثل uploadPanel.
- منطق currentFinish() توی JS دست‌نخورده موند: چون وقتی سلکتور مخفیه هیچ‌وقت
  مقدارش عوض نمی‌شه (خالی می‌مونه)، خودش خودکار برمی‌گرده به category محصول.
  یعنی نیازی به تغییر جداگونه‌ی منطق نبود، فقط UI باید بسته می‌شد.
- متن راهنمای پنل لایو هم شفاف‌تر شد: توضیح داده شده که این سلکتور فقط ابزار
  کالیبراسیون داخلی فروشنده‌ست (برای تنظیم چشمی ثابت‌های FINISHES توی
  live_render.py روی چند shade واقعی)، نه یه گزینه‌ی مشتری.

--------------------------------------------------------------------------
نتیجه
--------------------------------------------------------------------------
- نمای فروشنده (بدون ?client=1): سلکتور فینیش هنوز هست، برای کالیبراسیون.
- نمای کارفرما/خریدار (?client=1): سلکتور دیده نمی‌شه؛ فینیش همیشه و فقط از
  category محصول میاد — دقیقاً همون چیزی که فروشنده موقع آپلود مشخص کرده.
